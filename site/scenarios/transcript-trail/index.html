First time here? Set up Asterloom +
  1. Install the Mac preview. Download the ZIP from the v0.7.14 release, expand it, and open Asterloom. It supports macOS 13 or later on Apple silicon and Intel. There is no Windows installer in this release.
  2. Connect AI for creation. In a new game, choose Connect AI to create. In Connect your AI, select an available provider, complete its connection flow, select an available model, then choose Back to my game. Provider charges or usage limits may apply.
  3. Keep this guide beside the desktop app. Download the sample source below, or expand its preview to copy it. The website provides instructions and materials; create and play inside Asterloom.

Finished games play without a live AI connection. AI chat with Aster is a separate, optional connection. These guides use the published preview’s controls; its gameplay is older than the development screenshot on the homepage.

AI creation time and the chosen activity vary with the provider and source. The sample checks help you inspect the result; they are not a guarantee of a particular game or learning outcome. The samples are original fictional material for personal and family learning under the Asterloom license.

One step at a time

Let’s try it.

Follow these steps in the desktop app. Mark them here as you go.

  1. 01

    Upload the transcript text

    Download transcript-trail.txt. Choose Create a game → Upload files and add it. This kit is written timestamped text; no audio or video file is included.

    You’re ready when

    The source is Ready and includes speaker names with timestamps from 00:00 onward.

  2. 02

    Keep the conversation in context

    Open the source and find the 02:19 suggestion and the 02:27 response. Keep both in the material. Choose Done, then set Adults and Follow a procedure.

    You’re ready when

    The text explicitly distinguishes the blue-paper suggestion from an agreed decision.

  3. 03

    Create and read

    Connect your AI and model, then choose Create game with AI. When ready, choose Play game and work through the lesson's teaching before the quest.

    You’re ready when

    You can describe the draft, review, print, and installation stages.

  4. 04

    Follow the handoff

    Apply the transcript's checks in the generated activity. Printing waits for approval of the complete three-card set. Installation waits for readable, unclipped printed cards.

    You’re ready when

    You distinguish doing an action from passing the check required to move forward.

  5. 05

    Trace a failure to its stage

    Consider a clipped printed word, then a map card placed beside the tile. Find the transcript evidence for the stage responsible in each case, using Aster source search if helpful.

    You’re ready when

    A print failure returns to printing; a placement failure is corrected and checked at installation.

  6. 06

    Keep the original conversation

    Open Source materials and choose Download original file or Download readable text. Find the same timestamps in the saved text, then answer the checks below.

    You’re ready when

    You can verify what was agreed without treating a generated summary as the original meeting.

The payoff

What a good result looks like.

  • The game includes the supplied timestamped conversation as readable material.
  • You can distinguish an approved requirement from an unapproved suggestion.
  • You can trace dependencies and return a failed check to the right stage.

This kit demonstrates transcript-text import, not speech recognition, media playback, or synchronized checkpoints. Asterloom can also accept recordings and captions, but those are separate workflows requiring a matching media file.

Make the learning visible

Can you explain it?

Try answering from memory, then open the source-based answer to compare.

What is the agreed stage order and who owns each stage?

Draft: Claire. Review: Evan. Print: Theo. Install: Evan. Each next stage waits for the preceding stage's completion checks to pass.

Is blue paper a requirement?

No. Claire suggests blue paper at 02:19, but Rowan explicitly says at 02:27 that paper color has not been chosen.

What should happen if a printed card has a clipped word?

Return to printing: Theo reprints the card and repeats the print check. The transcript says not to change the approved wording to fix this print failure.

THE SMALL EXHIBIT HANDOFF
Original fictional transcript for Asterloom • NimeshBuilds
This is a written transcript of an invented meeting, not a recording of real people. Timestamps provide source locations. It teaches dependencies, acceptance checks, and the difference between a suggestion and an agreed decision.

[00:00] Rowan, coordinator: We have one tabletop exhibit to prepare. Our sequence is draft, review, print, and install. Each stage has a completion check. Finishing an action is not enough if its check has failed.

[00:22] Claire, writer: I will draft three caption cards. Each card must have a title and exactly two sentences. The first sentence names the object. The second explains what the visitor should notice. The three objects are a painted tile, a folded map, and a wooden compass model.

[00:49] Evan, reviewer: I will review the draft against the object list and the two-sentence rule. I can approve it only when all three cards pass both checks. If a card fails, I will name the problem and return it to Claire. We do not print a partly approved set.

[01:13] Rowan: So a returned draft goes back to writing, then through review again. The title does not count as one of the two sentences. Is everyone clear that printing waits for approval of the complete set?

[01:28] Claire: Yes. For example, a card titled “Folded map” could say, “This object is a map folded into four sections. Notice how the folds divide the route into smaller parts.” That has a title and two sentences, and it matches an object on our list.

[01:55] Theo, printer: Once Evan approves the complete set, I print one copy of each card. I check that all three titles are readable and no words are clipped. A clipped card is a print failure, not a reason to change the approved wording. I reprint it and check again.

[02:19] Claire: Could we use blue paper for every card? It might look good beside the map.

[02:27] Rowan: That is a suggestion, not today's decision. We have not chosen a paper color. The agreed print checks are readable titles and unclipped words. No one should treat blue paper as a requirement from this meeting.

[02:46] Evan: After all print checks pass, I can install the cards beside their matching objects. The last check is a one-to-one match: every object has its own correct card, and no card is beside the wrong object.

[03:03] Rowan: Agreed. Claire writes, Evan reviews, Theo prints, and Evan installs. If the map card is placed beside the tile, correct the placement and repeat the installation check. If a printed word is clipped, return to printing. Fix the stage that owns the problem, then verify it before continuing.

[03:29] Theo: I will report a stage as complete only after its checks pass. That will make our handoff clear: the next person knows what evidence supports moving forward.

If you get stuck.

I do not see an audio player.

That is expected. This kit contains a .txt transcript only. Timestamps locate text; they do not create an audio recording.

The game says blue paper is required.

Check the adjacent 02:19 and 02:27 passages. The later reply explicitly rejects treating the suggestion as a decision. Review that generated claim before sharing.
